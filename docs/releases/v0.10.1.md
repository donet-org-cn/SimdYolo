# SimdYolo 0.10.1：五代 YOLO 训练提速与保存模型对比

主库和训练核心保持纯 C# / .NET 10；CPU 使用 SIMD/intrinsics，GPU 调用系统 Vulkan/Metal API。应用运行不依赖 Python、PyTorch、TorchSharp、ORT 或 BLAS；Vulkan 不需要 CUDA Toolkit、cuDNN、cuBLAS 和 Vulkan SDK，需要兼容显卡驱动与 Vulkan loader。

## 本版功能

- YOLOv8n、Ultralytics YOLOv9t、YOLOv10n、YOLO11n、YOLO26n 检测头微调；冻结骨干/FPN，支持深度卷积、完整双头、自定义类别、SGD、取消和断点恢复。
- SIMD 激活/BN/SGD 与有限性检查、1×1零复制、连续行 im2col/col2im、直接点积 dW、有界临时矩阵复用。
- Vulkan 混合训练按计算量分派：小 GEMM 使用 CPU SIMD，较大 GEMM 使用 GPU；头部深度卷积、BN、损失和 SGD 仍在 CPU。
- 检测、实例分割、姿态推理，直接读取受支持完整 PT/ONNX/SYTRAIN 与类别标签；全部33个原模型随附件提供。
- ASP.NET Core 网页支持图片推理、检测数据导入、真实损失曲线、任务记录、取消/恢复、模型上传下载。
- 兼容旧 v8 原生训练归档；新归档包含单/双头参数、BN、动量与 YOLO26 固定调度，能直接推理和恢复。

训练仍限于检测头微调，不含全参数、分割/姿态或 Metal 训练。原 YOLOv9 DualDDetect/TripleDDetect、未知自定义结构不在训练验证范围；其他尺度未逐份验证。Metal 有推理实现，本轮未在 macOS 实机验证。普通 ONNX 用于推理，不能初始化本训练器；SYTRAIN不是PyTorch PT，暂不导出ONNX。

## 训练速度排名

i7-8700K / GTX1050Ti，128×128、FP32、2类、4线程、同初始权重与相同冻结特征。计时包含检测头前向、损失、反向、SGD和梯度清零，排除骨干、预处理、加载与保存。原版为官方 Ultralytics 8.4.0 头/损失和 PyTorch SGD，不是完整数据管线或全参数训练。

单位ms/步，越低越快，**粗体为同设备组第一**；各配置两独立串行窗口、预热10步、每窗512次更新，40窗口合计20,480次。CUDA每步同步，Vulkan包含上传/回读。

## 保存后的模型也做对照

COCO128固定拆成96张微调、32张微调留出验证，80类、256×256、2轮，各模型192次相同SGD更新。CPU对PyTorch CPU，Vulkan对PyTorch CUDA；两边的实际PT/SYTRAIN重新加载，运行完整骨干和检测头，使用相同输入与官方NMS/AP统计。

![保存模型的真实图片指标](https://raw.githubusercontent.com/hnlyf168/SimdYolo/v0.10.1/artifacts/training-results-0.10.1.png)

- 保存模型的P/R/mAP差值门槛10/10通过，mAP50–95最大差约0.088个百分点。
- 第1/16/96/192步直接参数门槛9/10通过；**v8 Vulkan/CUDA未通过项保持false**，未放宽容差。
- 额外对照发现PyTorch自身CPU/CUDA同样出现约0.012的参数/BN最大漂移；C#两后端对固定PyTorch CPU参数控制10/10通过。多步TAL离散匹配会放大FP32舍入，不声称参数逐位一致。
- 两边短程微调的验证精度都有下降。COCO128来自预训练所用COCO train2017，32张只对本次微调留出，不证明泛化或训练配方有效。

19项训练回归、117项推理回归、22,332项单步数值对照通过。原始结果、固定容差和实际DLL摘要见[验证目录](https://github.com/hnlyf168/SimdYolo/tree/v0.10.1/artifacts/validation/0.10.1)。推理性能表继续使用明确标注的[0.9.0冻结历史实测](https://github.com/hnlyf168/SimdYolo/blob/v0.10.1/artifacts/runtime-comparison-0.9.0.md)，没有冒充0.10.1重新测量。
