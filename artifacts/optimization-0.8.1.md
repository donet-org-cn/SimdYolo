# SimdYolo 0.8.1 实测：原版、我们的实现与 ORT

本轮使用同一台 Intel(R) Core(TM) i7-8700K CPU @ 3.70GHz、NVIDIA GeForce GTX 1050 Ti，FP32 / batch=1 / 640×640、12 线程。以下排名只来自本轮 0.8.1 的 176 个完整窗口；不拼接历史 0.7.x 测量。稳态输出与原版逐窗口对照 224/224 项通过。

0.8.0 → 0.8.1 的独立 ABBA 窗口中，18/44 组配置的新版本准备至首输出时间范围全部低于旧版本范围，3/44 组配置的稳态中位耗时范围全部低于旧版本范围。这里描述本次窗口的观察结果，不推断统计显著性或跨硬件表现。

每格为 ms + 名次；①最快，第一名加粗。各配置取独立窗口中位数的中位数，按未舍入值排名；完全相同的数值共享名次。只有两个窗口时，这个汇总值恰好是两个窗口中位耗时的平均数，一个异常慢窗口就可能改变排名。微小差距及范围重叠不能作为稳定胜出的依据。

本轮有 6 个模型/引擎组合的最慢窗口与最快窗口之比达到或超过 1.20；下方逐项列出实际范围，涵盖 ORT、原版与我们的实现，不把波动隐藏在汇总排名中。

表中的 † 表示：汇总数值虽比对应 ORT 小，但最快窗口对照、重复顺序或范围重叠不支持宣称稳定领先。不能借 ORT 的一个异常慢窗口宣称全面超越。

## 测量边界与正确性

稳态对照每配置 2 个进程，预热 60 帧，至少 4 秒和 40 帧。生命周期每配置 2 轮 ABBA，每个版本每轮两个全新进程；预热 60 帧（包括已测首帧），稳态至少 4 秒及 40 帧。

加载包含 YoloDetector 构造、后端初始化、模型解析和权重准备。首帧为首次 PredictRaw；GPU 包括输入上传、计算和全部输出回读。准备至首输出从托管 Main 首条语句开始，包含输入文件读取、会话构造和首帧，排除 dotnet 宿主启动和进入 Main 之前的入口 JIT。ProcessTotalMs 包含进程启动、预热、稳态、写盘和释放，不能用作进程至首输出延迟。

生命周期缓存模式：`inherited`。全新进程不会清空操作系统文件缓存或驱动缓存；应用管线缓存是否加载、命令重放次数及缓存文件状态保留在每个原始窗口中。管线缓存加载窗口：176/352；不把这些窗口称为硬件冷启动。

托管分配来自稳态 GC 累计分配量，扣除采样列表扩容；它是每帧创建量，既不是 RSS、存活堆大小，也不是峰值内存。公开输出数组计入分配。进程 CPU% 按累计 CPU 时间 / 墙钟 / 逻辑处理器数归一化；CPU ms/帧累加所有线程，因此可能大于墙钟 ms/帧。RSS 是进程驻留内存；GPU% 和显存是整卡采样，包含桌面及其他进程，不能解释为模型独占占用。

排名排除图像预处理、NMS 和掩码后处理，比较 FP32 原始模型输出；ORT CUDAExecutionProvider 允许部分节点运行于 CPU，不能描述为整图全部 CUDA。此轮没有 Metal 实机结果。

生命周期首帧与末帧已独立对照原版 CPU FP32：352/352 个窗口、896/896 个输出检查通过；验证文件通过生命周期 JSON 的 SHA256 绑定。端到端头按完整候选和实例附加字段配对，不用逐行排序误判并列 TopK。
